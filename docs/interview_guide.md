# 项目讲解稿（15 分钟）

## 1. 一句话定位（30 秒）

"Ames 房价回归，但重点不是模型本身，而是把特征工程、模型选型、线上服务、漂移监控串成一个可复现、可解释、可运维的闭环。"

## 2. 问题与数据（1.5 分钟）

- 1460 条样本、79 个原始特征，目标 SalePrice，偏度 1.88，存在 5.0 以上的长尾
- 先做数据校验：schema、重复 Id、目标缺失、业务范围（例如通过 `TotalBsmtSF > 7000`、`SalePrice` 区间等规则拦截脏数据）；校验报告落在 `reports/data_quality.json`
- 按价格五分位做分层切分，避免随机切分导致高价样本分布不均

## 3. 特征工程（4 分钟，重点讲）

**为什么值得讲**：这是唯一能体现"业务理解"的部分，模型本身谁都会调包。

- 14 个领域特征：总建筑面积、卫浴加权计数（半卫 0.5）、门廊面积、房龄/翻新龄/车库龄、质量×面积、地下室占比等
- 3 类编码策略分工：
  - 有序质量字段（Ex/Gd/TA/Fa/Po）→ 数值映射，保留序关系；缺失代表"没有该设施"→ 0
  - 低基数名义字段 → One-Hot，`handle_unknown="ignore"`
  - 高基数字段（Neighborhood 25 类）→ **折外目标编码**：训练时 5 折，每折用其余 4 折的平滑均值编码本行，避免目标泄漏；推理时用全量平滑统计，未知类别回退到全局先验
- 幂变换处理偏态、缺失指示变量保留缺失信息
- **量化结果**：消融实验 CV RMSE 0.12786 → 0.12599 → 0.12429，测试 R² 0.8881 → 0.9003（表格见 `reports/ablation.csv`）

## 4. 模型与选型（3 分钟）

- 5 个模型、每个 20 次 Optuna TPE 试验、5 折 CV，目标是对数空间 RMSE；MLflow 记录参数、指标、模型
- 选型规则：**只看 CV**，测试集只用于最终报告
- CatBoost CV 最优（0.11773）→ 部署；LightGBM 留出集 R² 更高（0.8912 vs 0.8735），但差距在 CV 噪声内（标准差 0.0025–0.0041），不能反过来用测试集挑模型
- Ridge 留出集 R² 0.28 的原因：Ames 有两套"部分产权出售"的极端样本（5642 sqft 卖 16 万美元），线性模型外推爆炸；这也是选择树模型的实证依据

## 5. 服务与监控（3 分钟）

- 单 Pipeline 落盘（含预处理），HTTP 层只做校验和编排
- 启动时加载一次模型（对比原教程每次请求 `joblib.load` 的性能坑）
- Pydantic v2：15 个必填字段 + 64 个可选字段；范围与枚举校验；批量接口上限 1000
- Prometheus 指标 + 请求级 JSON 日志 + `x-request-id`
- 漂移：PSI + KS；阈值 0.1/0.25；少于 200 条不算结论；稀有类别合并；只比较实际提供的字段
- 真实回放最大 PSI 0.119；注入漂移（面积 ×2.5、房龄 +30、未知社区）识别出 3 个特征

## 6. 工程与取舍（3 分钟）

- 60 个测试分三层：单元（变换器）、集成（Pipeline）、API；CI 跑 Ruff + mypy + pytest，覆盖率 62%
- Docker 多阶段 + 非 root + healthcheck，本地已完成构建与容器验收；公网托管按需选择云平台
- 主动不做的事：K8s、Kafka、Spark、自动重训——说明为什么不做，比堆技术栈更能体现判断力

# 高频追问与参考回答

## 方法论

**Q：为什么用 log 目标？**
A：SalePrice 偏度 1.88，取 log 后接近正态，平方损失不再被高价样本主导；评估时 `expm1` 回美元口径。RMSE 也变成近似的相对误差。

**Q：为什么不直接用测试集挑模型？**
A：测试集一旦参与决策就不再是测试集。我们预先定义"CV RMSE 最小"为规则，CatBoost 胜出；即使 LightGBM 留出集更好也不改，否则报告的 R² 会有乐观偏差。

**Q：CV 和留出集结论不一致，说明什么？**
A：两个模型差距小于一个标准误，属于噪声。可以改用重复交叉验证（5×3）降低方差，或做配对 t 检验；当前选择遵循预注册规则，而不是事后挑好看的数。

**Q：为什么不用深度学习？**
A：表格数据上 GBDT 仍是强基线；1460 条样本训不动大模型。做深度学习需要额外理由（例如多模态、序列），这里没有。

**Q：特征工程提升只有 2.79%，值得做吗？**
A：值得，但要诚实——树模型本身能拟合部分交互，所以增益有限。收益更多在**可解释性**：`QualSF`、`TotalSF` 成为 SHAP 前两名，说明它把业务知识显式表达出来了，而不是让模型自己猜。

## 特征工程

**Q：折外目标编码具体怎么防泄漏？**
A：`fit_transform` 时把训练集切成 5 折，每折的编码值只用其余 4 折的标签计算；`fit` 阶段再在全量数据上重建映射供推理使用。如果用全量均值编码训练行，目标信息会直接泄漏到特征里，CV 会虚高。

**Q：平滑系数 10 怎么定的？**
A：邻域样本量从几十到几百不等，`(sum + prior*10)/(count+10)` 让稀有类别向全局均值收缩。10 是常见默认值，没有单独调参——可以用嵌套 CV 搜索，但收益有限。

**Q：未知类别怎么办？**
A：目标编码回退到全局先验；One-Hot 由 `handle_unknown="ignore"` 全零处理。服务层对核心类别（Neighborhood/MSZoning）直接返回 400，避免静默给出不可信预测。

**Q：`MSSubClass` 为什么单独处理？**
A：它是数值编码的类别变量。CSV 里是整数 `20`，但 pandas 一旦有缺失会整列变浮点，序列化成 JSON 变成 `20.0`，类别词表就从 `"20"` 变成 `"20.0"`，编码全部错位。我在 `cast_and_fill_missing` 里统一做了 `20.0 → "20"` 的归一化，并加了回归测试。

## 服务与工程

**Q：为什么把预处理和模型打进一个 Pipeline？**
A：避免"训练时标准化、推理时忘了"的经典事故；也能防止在切分前做全局统计导致泄漏。代价是模型文件稍大（0.9 MB），可接受。

**Q：为什么不用 MLflow 直接提供在线推理？**
A：MLflow serve 适合原型，生产需要自定义校验、批量、指标和日志。我们只用它做实验跟踪和模型注册，服务层自己控制。

**Q：可选字段缺失时怎么保证预测可信？**
A：用训练集的中位数/众数填充，并在响应里返回模型版本；如果某列训练时全空，则跳过。更严格的做法是返回"置信度降低"标记——我做的是允许缺失但保持接口简单。

**Q：如何监控模型效果（不只是输入漂移）？**
A：当前没有真实标签回流，所以只能监控输入分布和预测分布。完整方案需要：成交后回填标签 → 计算滚动 MAE/R² → 与基线做显著性检验 → 触发重训。这是项目明确的局限。

**Q：PSI 为什么设 0.1/0.25？**
A：行业常用经验阈值（<0.1 稳定、0.1–0.25 关注、>0.25 显著漂移）。它本身不是统计检验，所以我又加了 KS 检验和最小样本量 200，避免小样本误报。

**Q：漂移误报是怎么发现的？**
A：第一次回放时 38 个特征被标记。排查后发现两类原因：① 只填核心字段的请求让可选类别全部变成 "Missing"；② `MSSubClass` 浮点/字符串不一致。修复方式是"只比较实际提供的值 + 类别归一化 + 稀有类别合并"，回放后最大 PSI 降到 0.119。

## 工程细节

**Q：为什么 Ridge 的测试 RMSE 是 LightGBM 的两倍多？**
A：两套部分产权出售的样本，面积极大但价格很低。线性模型沿面积外推，预测远超真实值；树模型受叶子节点约束不会外推。这也是为什么极端值要用分组误差分析而不是只看整体 R²。

**Q：如果要处理 10 倍数据量，哪里会先出问题？**
A：① 交叉验证调参（当前单次 20 试验 × 5 折要几分钟到十几分钟），需要分布式或早停；② 目标编码的 K 折实现要换成嵌套 CV / `category_encoders`；③ 预测日志 SQLite 要换 PostgreSQL/ClickHouse；④ 漂移计算要增量统计。Pipeline 和接口设计本身不用改。

**Q：如何保证可复现？**
A：固定随机种子（切分、Optuna TPE、模型）；所有路径和超参在 YAML；元数据记录库版本、训练行数、特征名和 clip 区间；CI 用合成数据跑端到端测试，不依赖网络。

**Q：如果上线后发现新社区，模型会怎样？**
A：目标编码回退到全局先验，One-Hot 全零，预测仍然可用但该特征无信息量；服务层对核心字段返回 400，避免静默错误。更合理的做法是把"未知类别"作为独立信号纳入监控并定期重训。
